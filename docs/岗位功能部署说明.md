# 岗位详情、简历投递和 MK 管理

本次功能基于提供的官网源码实现。正式网站尚未部署，正式 SMTP 和 HR 收件尚未验证。

## 已实现

- 首页、岗位列表和详情页统一读取数据库中已发布的岗位。
- 详情页包含介绍、职责、要求和右侧岗位信息；桌面双栏、手机单栏。
- Apply 打开确认弹窗；候选人登录后上传 PDF/DOCX 简历（最多 5 MB），确认岗位并提交。简历按文件内容检查，附件不放入 public 目录。
- 收件人固定为 hr@orangetalents.com；岗位页的联系人邮箱不会改变投递地址。邮件包含岗位、申请人联系方式、介绍和简历附件。
- 申请记录和待发邮件在同一数据库事务保存，防止重复投递；邮件状态与招聘进度独立。
- /admin/jobs 提供新增、编辑、草稿、发布和关闭；MK 使用自己的现有账号，获授权后导航和个人中心出现 Manage jobs。
- 已关闭的岗位保留详情链接，停止收取申请；草稿不公开。已有收藏和历史申请保留。Saved Jobs 已按确认设计改为列表，包含实时收藏数量、地点、合同类型、薪资、查看详情和移除；关闭岗位标记停止申请，草稿或已删除岗位标记不可用。

## 上线配置

1. 备份现有数据库和当前网站代码。先在测试环境验证；本包不会自动部署。
2. 使用 Node.js 22 或 24，以及现有 PostgreSQL。运行 npm ci。
3. 复制 .env.example 为 .env.local，填写现有 DATABASE_URL、JWT_SECRET、网站完整 HTTPS 地址和 SMTP 信息。JWT_SECRET 应沿用原值，除非计划让所有用户重新登录。
4. 确认 MK 的账号本人身份和数据库记录后，再将其邮箱加入 JOB_EDITOR_EMAILS；多个邮箱用英文逗号分隔。此权限只管理岗位。ADMIN_EMAILS 保留现有后台管理员配置，不要把 MK 放入此项来代替岗位授权。公开注册不允许使用已保留的管理邮箱。若 MK 尚无账号，应先由管理员核实并协助建立账号，再设置名单。检查数据库里是否有同邮箱不同大小写的重复账号，确认归属后再授权。
5. SMTP_HOST、SMTP_PORT、SMTP_USER、SMTP_PASSWORD、SMTP_FROM 必须全部有效。587 使用 STARTTLS，465 使用 TLS；需允许该账号使用指定发件地址，服务器需可连接邮件端口。不要使用普通网页登录密码冒充 SMTP 凭据。
6. 运行 npm run db:migrate。脚本可重复执行，新增表和字段，不覆盖已有岗位编辑；从原 jobs.json 导入原有两条岗位并保留原链接。原数据缺少的职责、要求、地点等请在后台补齐。此次迁移也新增 contract_type（合同类型），如 Permanent；与 Hybrid / Remote 等工作方式分开维护。数据库迁移完成后再启动新版。
7. 运行 npm run build，然后 npm start。反向代理必须转发正确的 Origin 和网站地址，允许至少 6 MB 的请求体及足够的请求时间。网站使用 Node 服务运行，不能静态导出。
8. 在部署平台配置每 5 分钟执行 npm run mail:retry 的定时任务，运行目录与网站目录相同，使用相同环境变量；监控非零退出及待处理状态。

## 邮件故障处理

- 缺少 SMTP 配置时，投递接口返回暂不可用，不会提示已提交。
- 已存储申请而邮件失败时，页面明确显示已保存、邮件需处理；候选人不应反复投递。明确失败由定时任务最多尝试 5 次。
- 超时、连接中断或发送成功后状态保存异常，可能导致收件结果不确定，此时标记 review；超过 10 分钟的 sending 也由定时任务转为 review，不自动重发。
- 先核对 HR 收件箱和垃圾邮件，按邮件主题中的申请编号查找。已收到：npm run mail:resolve -- 申请编号 --confirmed-received。确认没收到：npm run mail:resolve -- 申请编号 --confirmed-not-received，然后运行 npm run mail:retry。
- sent 只表示 SMTP 服务接受，不保证进入收件箱；上线需实际核验 HR 收件、附件和回复地址。
- 简历保存在 application_mail 的私有数据库字段中。数据库访问仅限服务和授权运维，按公司候选人数据保留规则管理备份与清理。

## 验收

1. 用 MK 账号建立草稿，确认公众看不到；补齐字段发布，检查首页、列表和详情；修改后刷新查看，关闭后应不能投递。
2. 用普通账号打开详情，检查两个 Apply 按钮、确认框、返回取消、手机布局；检查收藏、重复收藏、个人中心 Saved Jobs、View Job 跳转、Remove 后数量更新、空列表、手机布局，以及未登录后返回收藏页。
3. 使用专门的测试简历，确认允许收件后完成一次真实投递，核对 hr@orangetalents.com 收件和附件、申请记录。请勿用真实候选人资料做测试。
4. 重复投递、无登录、超大或伪装文件、无权管理应被拒绝；两人同时编辑时旧版本保存应提示冲突。
5. 模拟 SMTP 明确失败，修复后运行 mail:retry；人工检查不确定的发送记录。

自动测试必须使用独立 orange_review_test 数据库；测试会清空该库的相关表，脚本拒绝其他库名。设置 DATABASE_URL 指向此库后运行 npm test。SMTP 在测试中被替换为模拟器，不发送真实邮件。

回退时恢复旧代码并保留新增表/字段，勿删除已收到的申请和附件；若必须恢复数据库备份，先导出上线后新增申请。Next.js 已从 14.0.4 更新为 14.2.35，本次未进行跨主版本迁移。
